# 产品需求文档：标注校对助手（浏览器插件）

版本：1.1.0 ｜ 日期：2026-10-10 ｜ 类型：AI 应用 · 效率工具 · 浏览器插件

---

## 1. 背景与问题

数据标注团队在文本标注前普遍缺少一道轻量的"文本质量关卡"。标注文本常见五类问题：

| 问题类型 | 典型例子 | 现状痛点 |
|---|---|---|
| 错别字 | 因该→应该、按装→安装 | 人工看容易漏，直接污染标注结果 |
| 歧义词 | "期中/期终"、"权利/权力" 语境错位 | 无工具可查，依赖标注员语感 |
| 标点符号 | 中英文逗号混用、全角半角数字 | 平台审核工具不覆盖 |
| 语病 | "凯旋而归"语义重复、成分残缺 | 逐条判断成本高 |
| 逻辑问题 | 因果不当、前后矛盾 | 必须靠语义理解 |

- 标注平台的审核工具不覆盖"标注前的文本校对"环节；
- 直接把文本粘进聊天模型逐条问，效率低、结果无法沉淀；
- 涉密数据（客户委托、未公开内容）**不允许**发往公有云接口，但很多团队因此完全放弃了 AI 辅助。

## 2. 产品目标

让标注员在浏览器里**选中即校对**：页面内立刻看到一句话摘要，1 跳点击进入完整分类报告。

非目标（v1 明确不做）：
- 不做全页面自动扫描（DOM 依赖强、误报扰人，v2 再评估）；
- 不做标注结果质检（那是标注后的另一个环节，属于平台侧功能）。

## 3. 方案架构：双引擎 + 可切换后端 + 报告分屏

```
选中文本 ──► 规则引擎（本地、离线、零成本）
                │  错别字词典 101 条 / 语义冗余 16 组 / 标点格式规则 / 的得·在再提示
                │  原则：只报高置信问题，零误报优先
                ▼
            模型引擎（大语言模型，可切换后端）
                │  五类问题深度校对，按"输出格式"返回纯文本
                ▼
            报告合并（按原文片段去重 / 模型层优先覆盖规则层）
                │
                ├─► 悬浮面板：一句话摘要 + 查看详情链接
                │
                └─► 侧边栏：按【五类】分组渲染完整卡片
```

关键决策及理由：

1. **规则层零误报优先。** 规则引擎宁可漏报不可误报——一旦规则层出现"狼来了"，用户会关闭整个插件。语义类问题全部交给模型层。
2. **后端归一化为 OpenAI 兼容协议。** 无论 DeepSeek、通义、豆包还是公司内网网关，统一为 baseUrl + model + headers 三项配置。内网 vLLM/TGI/网关代理几乎都提供 OpenAI 兼容端点，一次适配即可接入。
3. **敏感数据模式是硬开关而非提示。** 开启后公有云后端直接停用（不是弹窗提醒），从代码路径上杜绝数据外发。这是把"数据安全"设计为产品约束而不是用户责任。
4. **站点权限按需申请。** 不默认索要 `<all_urls>`，用户配置后端后按 origin 单独授权，把浏览器权限暴露面压到最小。
5. **页面内即时摘要 + 侧边栏详情分屏。** Chrome 要求 `sidePanel.open()` 必须具备用户手势，由页面内按钮直接转发调用会被静默拒绝。改为：选中 → 浮动按钮 → 选区旁弹出简版面板（引擎状态 + 一句话摘要 + "查看详情"超链接）→ 用户点击链接唤起侧边栏看完整报告。链接点击是用户手势，唤起可成功。两次点击换取"悬浮不抢视线 + 详情不被压缩"。
6. **空结果必须区分状态。** 早期版本统一提示"未发现问题，也可能是模型层未启用或调用失败"，用户无法判断是否真的校对过。改为按引擎实际状态分别表述：均已校对 / 模型层未启用 / 敏感模式停用 / 调用失败（并附具体错误）。模型层失败时**无论有无结果**都显示错误横幅。
7. **模型层输出按统一格式的纯文本。** 五类问题逐条按 `- 【类型】"原文" → "建议"` 排版，末尾固定一行分类统计。后台按行解析为结构化条目，再与规则层结果按"原文片段"去重合并。优点是模型容易遵循（无需 JSON schema 容错），缺点是失去精确字符级定位——所以侧边栏去掉"一键替换"，统一用"复制建议"。
8. **精简校对原则。** 模型 prompt 与规则层共同执行"宁缺毋滥"原则：原文通顺无误就直接输出"未发现错误"五字，不强行挑错；专业术语、字段名、标签名不被视为错误。避免把改稿润色误报为纠错。

## 4. 用户故事

- 作为标注员，我在网页上选中一段文本，点击浮动"校对"按钮，**选区旁立即弹出摘要**（引擎状态 + 一句话统计 + "查看详情"链接），不抢占视线；
- 作为标注员，我点击"查看详情"，侧边栏打开并按【错别字】【歧义词】【标点符号】【语病】【逻辑问题】五类展示卡片，每条可复制建议；
- 作为标注员，我点"复制完整报告"，整份校对报告（含统计行）进入剪贴板，直接贴到 IM 或文档里走 QA 流程；
- 作为交付项目经理，我在设置页开启"敏感数据模式"，团队成员将无法把客户数据发往公有云；
- 作为管理员，我把内网网关地址发给团队，成员只需填地址即可使用，无需每人开通公有云账号。

## 5. 验收标准（v1.1）

- [x] 选中网页文本 → 浮动按钮 → 简版面板 → 链接唤起侧边栏，全流程 ≤ 3 秒（规则层）+ 模型延迟；
- [x] 规则层对样例集零误报（"不了了之""他在说了一遍"等合法用法不报）；
- [x] 模型层输出按统一格式解析率 ≥ 95%（容错处理缺括号、错别字等偏差）；
- [x] 同原文片段规则层 vs 模型层冲突时，模型层优先（可能给出更精准的修改建议）；
- [x] 敏感模式下任何代码路径均不向公有云发起请求；
- [x] 双后端切换无需改代码，仅需改配置；
- [x] 悬浮面板永远不超过两行高度（标题 + 摘要 + 链接），不遮挡原文。

## 6. 数据安全设计

| 层级 | 措施 |
|---|---|
| 传输 | 文本仅发送至用户显式配置的后端地址；无任何遥测上报 |
| 硬约束 | 敏感模式下公有云后端在 service worker 层被拦截 |
| 权限 | 站点访问权限按需申请，可随时在 Chrome 设置中撤销 |
| 存储 | 配置存于 chrome.storage.sync（含密钥时建议团队改用企业策略下发）；最近一次报告暂存于 chrome.storage.session（不跨重启保留） |

## 7. 迭代规划

- v1.2：全页面扫描模式（波浪线高亮）、自定义词典热更新；
- v1.3：标注规范注入——把团队自己的标注规范作为系统提示词的一部分，让模型按"你的标准"校对；
- v1.4：校对结果回流——badcase 自动积累为评测集，反哺提示词与规则词典（质量闭环）；
- v1.5：侧边栏内"按原文片段一键替换"——依赖本地规则层定位 + 模型层文本重构，纯客户端合成替换串（不恢复 JSON 协议）。
